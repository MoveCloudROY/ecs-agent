# Agent 用户编写接口剩余问题修复规划

日期：2026-10-20\
状态：阶段 A B C D 已实施并完成验证\
关联审查：[Agent 用户编写接口审查](2026-10-19-agent-authoring-api-review.md)\
前置修复：[P1 修复与验证记录](2026-10-19-agent-authoring-p1-fix-results.md)、[首轮 P2 修复与验证记录](2026-10-20-agent-authoring-p2-fix-results.md)\
实施结果：[剩余问题修复与验证记录](2026-10-20-agent-authoring-remaining-fix-results.md)

本规划覆盖审查中剩余的三组问题：DSL 声明与实际能力不一致、常用能力需要过多手动装配，以及 Prompt 与会话存在多个写入入口。目标是让声明能够完整落地，让基础 agent 通过公共入口完成装配，并让 Prompt 和历史修改具有明确的生效、持久化与恢复契约。

实施顺序为：修复已确认的行为缺陷，建立 Python 与 DSL 共用的装配流程，统一 Prompt 和历史写入，最后完成示例迁移与兼容验收。运行入口继续使用现有 AgentHandle，工具注册继续使用 register_tools，执行状态继续由 World 与组件持有。下文保留设计和验收要求；最终公共 API、逐项证据、兼容边界及实际测试结果见实施结果。

## 范围与完成标准

本轮交付包括 DSL 来源信息与字段映射、完整 agent 装配入口、调度依赖与重复安装检查、Prompt 更新与诊断接口、历史快照与修改接口，以及相关示例、持久化和 checkpoint 适配。

完成标准：

- DSL 声明的主 agent 和子 agent 能力实际生效；无法支持的配置在运行前明确报错。
- skills、用户工具和内置工具共存，装配过程不覆盖已有注册表。
- Python 与 DSL 通过同一内部流程生成等价的运行配置和可观察行为。
- 基础用法不要求作者手动创建常规组件、选择数值优先级或安装委派控制工具。
- Prompt 配置更新可预测地影响下一次请求，派生缓存与响应链不残留旧配置。
- 历史修改协调持久化、版本与缓存；失败不发布部分生效的历史或会话切换。
- P1 的执行入口授权与首轮 P2 的轮次、恢复、流式和工具注册契约保持成立。

本轮不新增同 World 多请求调度器、工具热替换、任意既有实体的通用补装接口或完整插件激活框架。原生 conversation tree 的写入缺陷仍是独立工作；新公共入口继续明确拒绝尚不支持的树配置，不能借统一历史接口宣称其已修复。

## 现状与设计依据

以下内容保留制定方案时的问题基线，用于说明修复动机。代码可能随实施变化；本表不表示这些缺陷在最新工作区中仍全部存在，是否关闭以验收证据为准。

| 剩余缺口 | 当前行为或依据 | 本轮处理 |
| --- | --- | --- |
| skill 工具表被覆盖 | [DSL 编译器](../../src/ecs_agent/dsl/compiler.py) 安装 skills 后重新添加空 ToolRegistryComponent | 调整初始化顺序，统一合并注册 |
| skill 来源缺失 | compiler 缺少 source_dir 时只告警并跳过；loader 未为每个 spec 保留来源上下文 | 保存逐 spec 来源，资源缺失时编译失败 |
| 子 agent 字段丢失 | compiler 已映射 tools，但未映射 skills、placeholders、triggers | 统一定义并补齐 child World 安装 |
| 部分装配易被当作完整运行时 | compile_agent_specs 未安装完整推理与工具执行循环 | 新增完整入口，保留旧接口的部分装配契约 |
| 手工装配繁琐 | [基础委派示例](../../examples/subagent_delegation_basic.py) 手动安装注册表、会话表、系统和控制工具 | 提供薄装配层和安装报告 |
| 调度配置重复 | 系统构造参数与注册参数都出现 priority；[SystemExecutor](../../src/ecs_agent/core/system.py) 按注册值调度，同优先级并发 | 收敛注册计划与依赖校验 |
| Prompt 更新可能不生效 | [解析入口](../../src/ecs_agent/prompts/message_assembly.py) 存在多个优先级来源；渲染结果会回写旧字段 | 统一配置入口，明确兼容字段与派生结果 |
| 渲染缓存漏掉配置变化 | [渲染缓存键](../../src/ecs_agent/systems/system_prompt_render_system.py) 未覆盖模板与用户占位值变化 | 补齐配置与依赖的缓存键 |
| 历史修改可绕过记录 | ConversationComponent.messages 可直接修改，而持久化需经过 [history API](../../src/ecs_agent/history.py) | 公共操作封装并迁移内置调用点 |

Prompt 缓存问题已通过无外部依赖的最小 World 复现：首次配置为 `Hello ${name}`、`name=Ada`，渲染得到 `Hello Ada`；替换为 `Goodbye ${name}`、`name=Bob` 后再次执行渲染，仍得到 `Hello Ada`。本轮将该场景固化为行为回归测试。

已有 [Python First RFC](2026-03-29-python-first-agent-authoring-api.md) 与 [Composable Agent Interface RFC](2026-07-18-composable-agent-interface.md) 提供了装配、冲突检查与兼容性分析。本轮采用共同装配和显式依赖的思路，运行职责以已交付的 AgentHandle 为准。

## 必须保持的运行契约

1. 工具注册不授予权限。DSL tools 继续表示权限映射，省略、空映射和显式拒绝的语义保持不变。
2. 工具执行器继续做最终权限与审批核验，不能将正确性重新交给系统排序。
3. 新轮、恢复和取消沿用 AgentHandle；装配层不创建另一套轮次状态或后台驱动。
4. 同一 World 保持单一驱动；内置 agent 系统继续遵循 query_active 的实体范围约束。
5. 已开始但结果未知的工具调用继续阻止自动恢复。修改 Prompt、历史或重置会话不能清除这类证据。
6. checkpoint 不恢复可执行审批缓存；新配置的恢复也不能重新初始化或覆盖已恢复的历史与轮次。
7. 调用方传入的 provider、session service 等资源保持原有所有权，装配器不隐式关闭它们。
8. 可选依赖按需加载，不因新增公共导出导致基础安装必须包含 MCP、观测插件或 pydantic。

## 统一定义与装配流程

内部流程收敛为：

```text
Python AgentDefinition / DSL AgentSpec 与来源信息
                  ↓
       归一化定义与 RuntimeConfig
                  ↓
       依赖校验与 AssemblyPlan
                  ↓
       安装组件 工具 系统及运行绑定
                  ↓
              AgentHandle
```

AgentDefinition 保存作者的 model、prompt、tools、skills、subagents 等定义。RuntimeConfig 保存系统组合及运行策略。AssemblyPlan 描述安装项、来源、依赖、顺序与冲突；这些对象不持有另一份可变会话历史。

DSL 保持可序列化的数据形式，通过适配器转换到同一内部定义。Python callable、provider 对象和系统工厂属于进程内绑定，不直接写入 checkpoint；需要恢复的绑定通过既有 resolver 或稳定引用重建。静态配置与依赖检查尽可能在调用 model_factory 和安装资源之前完成。

首版完整入口创建新的 World。安装失败时不返回部分可运行的 AgentHandle，并清理本次安装持有的资源。通用地补装到任意既有实体留待后续设计，避免把新建失败处理错误地等同于已有 World 的事务回滚。

## DSL 字段与资源映射

### 来源与校验

loader 为每个 spec 保留来源文件、agent 名称和资源基准目录。多文件合并后仍保留最终获选定义的来源，不从用户 metadata 猜测路径。

相对路径以声明文件所在目录解析，并沿用既有路径限制。内存构造的 spec 若使用相对资源路径，必须显式提供基准目录。旧 compile_agent_specs 的 source_dir 可作为没有来源信息的 spec 的兼容回退，不能覆盖 loader 已保留的来源。

先校验全部主从定义，再进行安装。缺失资源、未知占位符、冲突名称和不支持的字段组合应报告来源与字段路径，例如 `researcher.skills[0].path`。不能出现成功返回但静默跳过配置的情况。

### 注册表与 skills

在安装任何 skill 或内置工具前初始化目标实体的工具注册表。所有工具安装复用 register_tools 的校验与合并路径，不重新挂载空表。

load_skill_details 等共享内置工具每个实体安装一次。同一受框架管理的安装项可复用；用户工具或不同定义占用相同名称时明确报错。不得将 register_tools 的拒绝重名契约改成无条件覆盖。

内部引入带来源的 SkillRef，区分本地路径声明与按名称继承。当前 DSL skills 是路径，而 SubagentConfig.skills 是名称列表，二者通过适配器转换，不能直接混用。子 spec 的本地 skill 直接安装到 child World，不为了方便查找而先赋予父 agent 相同能力。

### 主从能力一致性

| 字段 | 主 agent 映射 | 子 agent 映射 |
| --- | --- | --- |
| model | 解析 provider 绑定 | 为 child World 解析绑定，保持资源所有权契约 |
| prompt 与 placeholders | 生成 SystemPromptConfigSpec | 生成子实体的独立配置 |
| triggers | 生成 UserPromptConfigComponent 并安装归一化系统 | 对委派给子实体的输入应用规则，并安装相同能力 |
| skills | 按主 spec 来源安装 | 按子 spec 来源安装，与显式继承分别处理 |
| tools | 编译本地权限 | 编译本地权限，并按既有继承策略与父权限合并 |
| metadata | 保留描述信息 | 同样保留，不作为隐式能力开关 |

允许某个工具名称只表示权限，不产生 handler。工具实现来自 Python 注册、skills 或框架内置工具。子 agent 的工具继承、父权限继承和本地权限仍是独立配置，不改变现有 InheritancePolicy 的默认语义。

对无法安装所需系统的自定义 child profile，编译时报告能力缺失。过渡版本尚未支持的字段组合应明确报错；本轮验收完成前必须补齐上述已承诺的映射。

## 完整 agent 装配入口

拟议用法：

```python
agent = build_agent(
    AgentDefinition(
        model=model,
        prompt="你是研究助手。",
        tools=[search],
        subagents={
            "researcher": AgentDefinition(
                model=research_model,
                prompt="完成研究任务并返回结论。",
                tools=[search],
            ),
        },
    ),
    runtime=RuntimeConfig(),
)

result = await agent.run_turn("研究这个问题", max_steps=20)
```

build_agent 返回现有 AgentHandle，不引入第二个运行手柄。基础运行时安装会话、Prompt 渲染、推理、工具执行与错误处理；启用子 agent 时同时安装注册表、会话表、委派和控制工具，以及所选同步、后台或等待模式需要的系统。

主 agent 与 child World 共用基础安装逻辑。子实体所有权、继承、委派结果封装和 child session 关联保留为明确的附加步骤。现有 child runtime profile 通过适配器提供系统计划，避免维护两套独立默认流程。

### 调度与重复安装

最终系统注册计划是唯一调度依据。逐步废弃系统构造函数中仅保存的 priority 参数，旧调用保留兼容期，不能无声改变数值注册的行为。

作者通过具名步骤和 before/after 约束表达依赖。装配器检查依赖环，生成确定的执行组和数值优先级；存在读写依赖的系统不得进入同一并发组。注册顺序不能替代组间顺序。

约束必须反映具体能力。例如会修改 phase 的输入 trigger 先于依赖 phase 的 Prompt 渲染；工具执行先于依赖工具结果的 replanning。不能用一套固定默认顺序掩盖这些差异。

实体组件按实体和语义槽位检查冲突。World 级系统按职责、配置与适用范围检查：相同受管理安装项可以复用，不兼容配置报错；不能仅按类名去重，也不能合并应独立创建的有状态系统实例。子 World 使用独立实例。

装配报告应包含组件与工具来源、具名步骤、实际 priority、并发组、依赖和诊断。完整入口交付前检查必要运行系统齐全；检查失败不能退化为空转直至预算耗尽。

### 部分装配接口兼容

compile_agent_specs 目前返回 `(EntityId, World)`，调用方通常继续注册运行系统。该接口保持部分装配语义，通过共同装配器的兼容模式实现，不直接变成完整构建入口。

新增面向 specs 的完整构建入口，走同一归一化与安装流程并返回 AgentHandle。基础 DSL 示例迁移到完整入口后，删除其重复手写系统安装。低层示例可以保留旧接口，但必须说明返回的是部分运行时。

## Prompt 配置与渲染

### 配置权威与兼容字段

以 SystemPromptConfigSpec 作为新接口的配置来源，字符串 Prompt 自动归一为 inline 模板。RenderedSystemPromptComponent 是派生结果。LLMComponent.system_prompt 与 SystemPromptComponent 保留兼容用途，新接口不将它们作为独立写入入口。

旧实体迁移时，单一来源可以转换为统一配置；多个来源内容冲突时报告候选来源并要求调用方明确选择，不依靠当前解析优先级猜测作者意图。兼容回写应标明派生属性，不能形成“渲染结果再次成为模板”的循环。

拟议操作为 `agent.set_prompt(prompt_config)` 与 `agent.inspect_prompt()`。公开 Prompt 修改仅允许在没有活动驱动和未结束轮次时执行。paused、blocked、legacy 或尚未显式结束的失败轮次不能通过修改 Prompt 改变后续恢复的上下文。phase 等内部动态变化继续通过框架受控路径处理。

set_prompt 统一完成校验、配置版本更新、必要的持久化、渲染缓存与 Responses 响应链失效。相应配置记录提交失败时不发布新版本。动态 callable 通过明确绑定恢复，不能以 repr 或不可执行的 JSON 片段冒充可恢复配置。

### 缓存与诊断

渲染缓存键覆盖模板内容、配置版本、本次解析出的用户占位值、内置 provider fingerprint 和影响渲染的配置。动态占位函数每次渲染只求值一次，同一份值同时用于缓存键与正文。

文件模板采用显式重新加载，安装或更新时获得内容快照，不默认监视文件。phase、压缩摘要、scratchbook 等动态依赖继续参与失效判断。保留稳定前缀与动态尾部拆分，避免普通轮次变化无谓改写稳定前缀。

inspect_prompt 返回最终稳定前缀、动态尾部、配置版本、各部分来源及缓存依据。诊断读取最近渲染快照或无副作用的预览，不消费上下文队列，不执行有副作用的 trigger；尚未渲染时明确标示，不能将旧快照冒充新配置结果。

checkpoint 恢复后按恢复的配置和运行依赖重建派生缓存，不能直接信任旧 RenderedSystemPromptComponent。旧数据缺少配置来源时沿用明确的兼容解析，不覆盖现有 phase 图重绑定与恢复契约。

## 历史读取与修改

复用 history.py 与既有 session service，不另建一套历史存储。拟议公共操作如下：

| 操作 | 契约 |
| --- | --- |
| history_snapshot | 返回消息副本、history ID 和 revision；修改快照不会改变运行状态 |
| replace_history | 校验消息与工具协议，要求 reason，持久化后更新历史及 revision，并使相关缓存失效 |
| reset_session | 要求 reason，创建新会话身份，保留旧记录和关联，成功后切换绑定 |
| run_turn | 保持提交新用户输入并开启执行的唯一推荐入口 |

消息快照需要复制 Message 及其嵌套内容；仅将原列表包装成 tuple 不足以隔离可变对象。历史替换可携带期望的 history ID 与 revision，拒绝使用过期快照覆盖较新的历史。

公开替换和重置仅允许在没有活动驱动、没有未结束轮次且工具历史闭合时执行。验证调用与结果配对、顺序和唯一性，禁止丢弃未确认执行证据。内部压缩可以在运行中发生，但必须通过专用的受控写入路径保留轮次输出与工具状态；不能复用公共状态限制后再绕过它。

### 提交顺序与失败处理

历史修改按“准备数据与记录 → 提交可见版本 → 更新运行投影”的顺序实现。提交必须有单一可识别的生效点；内存投影可从已提交记录恢复。

替换记录必须能重建完整、有序的目标历史，包括保留消息的引用、必要的新消息内容及协议字段。会话切换先准备新记录与 writer，再提交关联切换。失败后释放本次新资源并保留旧绑定，不能先写入已生效的 reset 再尝试创建新会话。

复用当前 store 的事务或原子 head 发布能力；若其不足以实现上述契约，先补充最小提交原语及失败恢复测试，不能用顺序调用多个 append 宣称具有原子性。进程崩溃后以持久化的提交状态重建投影，未提交的准备数据不得表现为已完成操作。

替换历史同步使 Responses 响应链、旧用户 Prompt 渲染和基于消息位置的派生状态失效。新会话遵守既有生命周期转换，不能复用上一轮结果作为新会话输出，也不能删除未知工具副作用证据。

### 内置路径迁移

ConversationComponent.messages 暂时保留低层兼容。公共示例停止直接修改，内置输入、模型输出、工具结果、归一化、上下文注入、压缩与 session 操作逐步统一到受控路径。确需直接写投影的恢复代码必须明确其记录来源及失效责任。

保留原始用户输入和模型实际消费的归一化内容之间的关联。诊断、历史替换与恢复不得触发 script trigger 再执行，也不得把已经持久化的工具结果重复追加。

## 行为验收矩阵

测试以 FakeModel、请求捕获、计数 handler、临时资源目录和可注入失败的 session store 为主。断言实际请求、执行次数、记录与恢复结果，不能只检查组件是否存在。

| 编号 | 场景 | 必须满足 |
| --- | --- | --- |
| D1 | 安装 skill 后再注册普通工具与委派工具 | 工具及 handler 全部保留，skill 工具实际可调用 |
| D2 | 不同目录定义同名相对 skill 路径 | 分别按声明来源解析；缺失资源错误可定位 |
| D3 | 子 agent 同时声明 skills、placeholders、triggers | 实际请求含正确渲染与归一化内容，子工具能执行，父实体未被意外安装相同能力 |
| D4 | DSL 权限省略、空映射、拒绝与继承组合 | 保持 P1 语义，禁止调用的 handler 执行次数为零 |
| A1 | 等价 Python 与 DSL 定义 | Prompt、工具 schema、权限、系统依赖及运行结果等价 |
| A2 | 旧部分装配与新完整入口 | 旧调用补系统后仍正常；新入口无需补装且每步执行一次 |
| A3 | 缺失系统、重复安装、冲突与依赖环 | 运行前明确报错；合法重复安装不产生额外执行 |
| A4 | phase trigger 与渲染、执行与 replanning | 依赖方观察到本轮更新；不依赖同优先级注册顺序 |
| A5 | 同步委派、后台与等待模式 | 所需运行系统齐全，无遗漏安装造成的空转 |
| P1 | 模板从 Hello Ada 改为 Goodbye Bob | 下一次渲染和实际请求使用新内容 |
| P2 | 动态变量与显式模板重新加载 | 每次渲染只求值一次，更新能失效，未重新加载时保持已接受快照 |
| P3 | phase、摘要、scratchbook 更新 | 动态部分更新，稳定前缀满足既有字节等价契约 |
| P4 | Prompt 诊断与旧字段冲突 | 来源可解释；诊断不执行 trigger 或消费队列；迁移不静默选错来源 |
| H1 | 修改返回的历史快照 | 原消息与嵌套内容保持不变 |
| H2 | 历史替换及过期 revision | 正确更新记录与缓存；过期编辑被拒绝 |
| H3 | 提交记录、新 writer 或会话切换失败 | 旧可见历史与绑定保持，准备资源有收尾，恢复不误判操作已完成 |
| H4 | 活动、暂停、blocked 或未知工具结果时修改 | 拒绝不允许的操作，执行证据完整保留 |
| H5 | 压缩、归一化、替换后继续运行 | 当前轮输出归属正确，输入与工具结果不重复，旧响应链不复用 |
| R1 | checkpoint 保存、加载与接续 | 配置及历史正确恢复，缓存重建，审批重新核验，无意外重新装配 |
| R2 | 同 World 多实体与取消恢复 | 沿用执行范围和单一驱动契约，其他实体不被误执行 |
| R3 | 从较早 checkpoint 恢复带 script trigger 的轮次 | 结合持久化执行记录判断是否已开始或完成；结果未知时阻止自动重放，旧格式证据不足时明确报告，不能仅依赖快照中的缓存判断安全 |
